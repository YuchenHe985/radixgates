# 4× RTX 4090 Deployment and Benchmark Report

This report records a real deployment of the RadixGates upstream snapshot in front of SGLang on a rented 4× RTX 4090 host. It is an engineering execution record: environment, validation matrix, measured results, deployment failures, recovery actions, and limits. It is not a production acceptance test or a controlled hardware study.

**Run date:** 2026-07-27  
**Evidence:** [`sglang_parallelism_runs.csv`](../../benchmarks/results/real_gpu/sglang_parallelism_runs.csv) and [`real-gpu-results.md`](../real-gpu-results.md)  
**Gateway revision:** delivered project preserved at tag [`upstream-snapshot`](https://github.com/YuchenHe985/radixgates/tree/upstream-snapshot)

## Executive summary

- Brought up four SGLang deployment modes behind the gateway: four independent replicas (DP=4), prefill/decode disaggregation, tensor parallelism (TP=4), and tensor plus expert parallelism (TP=4 + EP=4).
- Completed all measured requests: **40/40** for DP, **30/30** for PD, and **20/20** for both TP and EP.
- Verified prefix affinity on DP using repeated system prompts: warm time to first token was **37.9–62.3 ms**, versus **86.6–113.3 ms** for the first request to each prefix.
- Diagnosed four startup blockers involving the CUDA image/driver contract, removed SGLang flags, NCCL initialization in Docker, and a renamed expert-parallel flag.
- TP and EP required `NCCL_P2P_DISABLE=1` on this host. Their latency therefore describes this recovered configuration, not an unconstrained RTX 4090 PCIe baseline.

## Project evolution and scope boundary

These GPU measurements were collected against the gateway as delivered, before the reliability work now present on `main`. They validate the original deployment path and the DP/PD/TP/EP configurations. They do **not** benchmark the later health-aware failover, circuit breaker, bounded-load routing, admission queue, retry policy, or expanded telemetry.

The current implementation preserves the evaluated baseline at `upstream-snapshot` and evaluates the later gateway changes separately through repeatable fault injection and real llama.cpp workers. See the repository [README](../../README.md) and [`RELIABILITY.md`](../RELIABILITY.md). Keeping these evidence sets separate avoids attributing later behavior to an earlier hardware run.

## Measured results

Each row is one completed run from the original demo harness. Latency percentiles cover successful requests in that run.

| Mode | Success | P50 | P95 | TTFT evidence | Notes |
| --- | ---: | ---: | ---: | --- | --- |
| DP=4 | 40/40 | 1,215 ms | 2,300 ms | warm 37.9–62.3 ms; first request 86.6–113.3 ms | Four independent replicas; total wall time 2.4 s |
| PD 1P+1D | 30/30 | 2,544 ms | 4,973 ms | medians 94.7 / 93.9 / 117.3 ms for short / medium / long prompts | Mooncake backend; total wall time 5.1 s |
| TP=4 | 20/20 | 4,836 ms | 6,475 ms | median 87.0–89.2 ms | `NCCL_P2P_DISABLE=1`; about 22.3 GB used per GPU |

The DP script printed an estimated 4× improvement by extrapolating from request duration. No single-GPU baseline was measured in this run, so that value is not treated as a measured scaling result.

## Deployment incidents and corrective actions

| Symptom | Diagnosis | Corrective action | Operational consequence |
| --- | --- | --- | --- |
| Container rejected at startup with `unsatisfied condition: cuda>=13.0` | The floating `latest` SGLang image required a newer CUDA runtime than the installed driver could support | Pinned `lmsysorg/sglang:v0.5.16-cu129-runtime` | Reproducible image/driver contract; avoid `latest` in deployment |
| Server exited on `--enable-prefix-caching` | The flag had been removed; radix prefix caching was enabled by default in this SGLang version | Removed the obsolete argument from all Compose files | Configuration became version-compatible without disabling caching |
| TP entered a restart loop at `ncclCommInitRank` | NCCL communicator creation failed in this Docker/host configuration | Added `ipc: host`; disabled P2P and IB for this run | TP/EP became usable, but communication used a slower path and is a benchmark confounder |
| EP exited on `--enable-expert-parallel` | The version expects `--ep-size 4` | Replaced the removed flag | Four TP/EP ranks started and were verified in logs |

Recovery configuration used for TP and EP:

```yaml
ipc: host
environment:
  - NCCL_P2P_DISABLE=1
  - NCCL_IB_DISABLE=1
```

## Operational decisions

- **Pin images and record versions.** A floating container tag broke the deployment before any application code ran.
- **Treat topology as input.** DP avoided inter-GPU communication; TP and EP exercised NCCL and exposed host-specific constraints.
- **Keep long work independent of SSH.** Model downloads, startup waits, and benchmarks were moved into detached host-side scripts after intermittent client connectivity.
- **Budget model storage explicitly.** The 119 GB free disk could not retain the 8B, 32B, and MoE checkpoints together; cache cleanup was scheduled between model families.
- **Preserve failure context.** Startup log signatures from this work became inputs to the companion [`llm-serving-eval-kit`](https://github.com/YuchenHe985/llm-serving-eval-kit) doctor command.

## Reproduction outline

```bash
# Pin the compatible runtime instead of using latest.
docker pull lmsysorg/sglang:v0.5.16-cu129-runtime
docker tag lmsysorg/sglang:v0.5.16-cu129-runtime lmsysorg/sglang:latest

# Example: four data-parallel replicas behind the gateway.
MODEL_PATH=NousResearch/Meta-Llama-3-8B-Instruct \
  docker compose -f docker-compose.dp.yml up -d
curl -fsS localhost:8080/health
python3 examples/dp_demo.py

# Example: TP=4 after applying the NCCL recovery configuration above.
CUDA_VISIBLE_DEVICES=0,1,2,3 TP_SIZE=4 \
  MODEL_PATH=Qwen/Qwen2.5-32B-Instruct \
  docker compose -f docker-compose.tp.yml up -d
python3 examples/tp_demo.py
```

## Interpretation limits

- One run was retained per cell; there are no confidence intervals.
- Prompt and output token counts were not fixed across every mode.
- TP and EP ran with NCCL P2P disabled, so their latency is not a clean measurement of RTX 4090 PCIe capability.
- The functional “enterprise” prompts were reference workloads, not traffic from a named customer.
- The A100 comparison used a different SGLang version, driver, memory capacity, and deployment path. Ratios are reported as observations, not attributed to NVLink alone.

For the normalized cross-platform table and the rerun plan, see [`real-gpu-results.md`](../real-gpu-results.md).
